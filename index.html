为什么不能直接查：学校接口 pay.wxstc.cn 的响应里没有 Access-Control-Allow-Origin，浏览器会按同源策略把跨域响应丢掉， 页面拿不到数据；GitHub Pages 是纯静态托管，也改不了别人的响应头。 所以从 Pages 上取数必须经过一个「中转」——中转只负责转发一次请求， 不保存任何 Cookie、账号或查询结果，因此多人同时用依然互不影响。

三条路：①直接用历史数据（仓库里已经放好按楼栋/房间分好的真实台账，截至页面上标注的时间，完全离线、人人可用）； ②点「自动检测可用中转」，能用的直接选（2026 年起公共代理基本只支持 GET，多半只剩本机/自建中转可用）； ③自己部署一个中转（relay/ 里的 Cloudflare Worker 或本机 Node）。

逐个实测：已保存 / 已填 / 链接参数 / 本机中转 / 本站同源 / 公共代理
都没有？自己弄一个（免费，5 分钟）
  1. Cloudflare Worker（推荐，得到 https 地址）：登录 Cloudflare → Workers & Pages → Create Worker → 把仓库里 relay/worker.js 的内容整个粘进去 → Deploy，得到 https://xxx.workers.dev， 填到上面的「中转地址」→ 点「保存并测试」。
  2. 本机 Node（最省事）：克隆仓库后执行 node relay/server.mjs，再打开 http://127.0.0.1:8787/ —— 这个地址本身就同源，直连即可，检测也会自动认出它。
  3. 中转只转发一次请求、不落任何数据；不用了把地址清掉即可。
